# Vicon／OpenSim SO workflow

这套流程从步行支撑期试跑发展而来。方法验证范围见[验证说明](validation.md)。SO 在给定运动和外力下估计肌肉力与激活；不要求先运行 CMC，也不直接输出关节接触力。

## 1. 确认任务与配置

- 受试者、试次、L/R侧别、动作类型、输出目录，以及使用 IK 或 RRA 路线；只有需要对照时才计算两者。
- 记录模型版本、原版膝关节约束、肌肉参数来源、肌肉生理选项、激活目标指数、优化器容差及每帧迭代上限。
- 每批开始前在对话框询问“这批 SO 用哪套最大等长肌力？”选项为“原版 Gait2392”或“将 Rajagopal 2016 最大等长肌力移植到 Gait2392”。收到选择后再准备计算。IK 与 RRA 对照使用同一选项，除非用户明确要比较肌力设置。选择移植时，预检官方 `Rajagopal2016.osim`，并保存[肌力来源与逐肌肉审计](execution.md#muscle-strength)。
- 询问是否新增滤波；已有明确且适用的决定可复用。可以举“四阶巴特沃斯低通6Hz、双向零相位”的例子，但不能默认采用，也不能假设 IK 已经滤波。运动学与测力分别确认，跑步须单独论证。
- 不默认上传 GitHub，不自动运行 CMC／JRA，不自动修改肌肉强度、肌腱长度或模型自由度。

## 2. 环境和输入预检

- 验证 OpenSim 原生工具和生成／复核脚本环境，记录版本；本次已验证原生 OpenSim 4.5 CLI＋Python API 4.5.2。
- 必需：肌肉模型、IK或RRA运动、ExternalLoads.xml及实际测力文件、原始帧／时间映射、足／力台指定、接触完整性和力台归零处理记录。
- 核对来源和文件SHA256；至少存在一条明确的腿到力台指定，但这一点本身不能证明同时接触的全部外力已测得。
- 检查单位、运动坐标名、关节锁定、轴向／刚体变换、时间覆盖和有限值；模型应能初始化，质量／惯量有效，肌肉和对应路径存在。
- IK 路线用来源一致的缩放／锁定模型；RRA 路线用选中候选的调整模型和对应运动，不能误用诊断候选或另一个试次的质量参数。
- 带RRA复核警告时明确技术试跑与正式分析的用途。缺输入、校验不符、外力接触问题应在对话中提示，等待修复或用户明确跳过／保留诊断；批次可继续其他已批准的独立试次。

## 3. 确定每个 L/R 计算窗口

- 步态沿用原始20N足／力台事件；保存原支撑期起止、裁掉的头尾、原始帧号／序号、总帧数及百分比。
- 在目标事件内使用外力完整的连续区间；所有同时存在的对侧实测外力也必须施加，不能只因命名为R而删掉左侧力。
- 不延长至台外接触未知区间，不跨缺失段拼接，不把部分支撑期重新映射为完整0–100%。
- 比较 IK 和 RRA 时使用共同时间窗、同一外力、相同执行器及优化设置；统一采样方案须记录重采样方式与影响。
- 滤波如需实施，先检查足够的上下文和边界处理，不对极短裁剪段盲目滤波；任何端点求导影响均保留提示。

## 4. 配置肌肉模型与执行器

- 保留原模型肌肉、肌肉控制边界和关节约束，检查肌肉数量与输入版本一致。
- 为自由骨盆配置所需残余执行器，并按研究方案配置关节储备执行器；明确单位、optimal_force、控制边界和成本。
- 不直接照搬RRA中强大的理想关节执行器，让其替代肌肉承担关节力矩。
- 本次技术试跑：92条肌肉、18个自由广义坐标，18个对应的CoordinateActuator，optimal_force=1，控制范围±1000。平移输出N，旋转输出Nm。这是本次数值方案，不是通用生理阈值或对所有模型的推荐。
- 生成可复查的SO模型和SO_setup.xml。use_model_force_set=true；本次激活指数2、use_muscle_physiology=true、每帧最多100次、优化器容差1e-4。

## 5. 运行 SO 并保存原始证据

- 使用AnalyzeTool中的StaticOptimization，保存原生运行日志、退出码、配置和过程状态。
- 标准输出：*_StaticOptimization_activation.sto、*_StaticOptimization_force.sto、*_StaticOptimization_controls.xml。
- 另存相同模型／运动／外力下的ID作为储备力矩诊断参考；SO内部已求解相应动力学，已有ID结果不是其必需输入。
- 不要求像TWSA一样运行200个候选。SO的迭代是每个采样时刻的肌肉分配优化，含义不同。

## 6. 逐帧数值核查

- 不以退出码0或文件存在认定成功；检查OPTIMIZATION FAILED、失败时间及约束违背。
- 验证输出时刻、样本数、列名、有限值和肌肉／执行器边界；数值失败时输出中可能仍有数值。
- 失败帧保留原始输出，但从验证后数据中屏蔽；曲线断线，不补成成功帧，不直接用于统计。
- 汇报“1.36s／原始603帧／整条序号137/216／原支撑期49.43%”等位置；有连续异常时汇总片段及支撑期头中尾。
- 重试只针对已解释的数值问题，保留原记录；不能自动提高肌力或残余上限来掩盖不合理数据。

## 7. 生物力学质量复核

- 分开报告骨盆平移残余力N、骨盆旋转广义残余Nm、关节储备Nm以及肌肉力N；不同坐标单位不得混在一个最大值中。
- 给出每关节储备峰值／同路线ID净力矩峰值，低力矩分母单独标记；不是对每个瞬时近零净力矩机械求百分比。
- 检查肌肉激活接近上下界、持续饱和、肌肉力尖峰、异常同步共收缩和被残余／储备承担的负荷。
- 保留标记误差、原IK与RRA的足踝和骨盆变化、质量／质心调整及模型参数限制；残余达标、SO收敛都不能独立证明生理有效。
- 有EMG时用于合理的时序／模式对照；SO激活不是实测EMG。没有EMG不自动判失败，但不能称为已通过EMG验证。
- 所有质量阈值应说明是用户研究设置、数值容差还是有出处的建议，不能把本地选择称为统一官方标准。

## 8. 提取可比较的指标

- 仅从肌肉列提取肌肉力／激活；force.sto还可能含残余、储备及其他力，必须分类。
- 每肌肉：峰值、均值、峰值时间、肌肉力时间积分和激活积分；额外保留原单位曲线。
- 跨受试者力可按实测体质量归一化为N/kg，或按实测体重力归一化为BW；不使用逐试次RRA调整后的总质量作为默认分母。
- IK/RRA的成对指标基于共同有效区间；失败帧不填零，积分不跨缺失区间连接。
- 被裁掉阶段的峰值和积分不可恢复；部分窗口只能报告该窗口指标，不能冒称完整支撑期／步态周期。
- 单条技术试跑只做描述性对照。正式分析以受试者为独立单位，重复试次需按设计汇总或建模，不能把帧数当样本量。

## 9. 报告、复现和后续交接

- 每试次／L/R目录保存输入副本或可追踪路径、SHA256、配置、模型、setup、原生日志、肌肉力／激活、异常帧、质量指标和MD报告。
- 固定Python脚本输出肌肉力／激活曲线、残余／储备和必要的IK/RRA运动对比，保留原始时间及支撑期百分比。
- 在对话中明确：成功帧／总帧、失败位置、大残余、饱和肌肉、窗口裁剪及需修复的输入。不会只报“运行完成”。
- 结束后再次校验原始输入未变；区分“求解成功”“带质量警告”“数值失败”“输入受阻”。
- 后续JRA必须使用对应路线的模型、运动、外力和肌肉／执行器力。CMC另行配置与验证，不自动串接。
